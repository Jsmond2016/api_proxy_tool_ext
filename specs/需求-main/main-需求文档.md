# main 需求文档

## 开发分支

`main`

## 背景与目标

用户在 Options 面板的接口表格中测试 Mock 接口后，若响应不符合预期，需要能够从测试结果弹框直接进入对应的 Apifox 接口页面修改 Mock，减少重新查找接口的操作成本。

## 需求范围

| ID  | 需求点                                                  | 验收标准                                                                                              | 状态   |
| --- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------ |
| R1  | 测试结果弹框复用接口信息字段已有的 Apifox 网页地址。    | 跳转地址与表格“接口信息”中的接口名称链接一致，包括已有 `link` 和根据项目 ID、接口 ID 生成的兜底地址。 | 已验证 |
| R2  | 在测试结果弹框右下角“关闭”按钮左侧增加“去改 mock”按钮。 | 用户点击“去改 mock”后，在新标签页打开当前接口对应的 Apifox 网页；“关闭”按钮行为不变。                 | 已验证 |
| R3  | 避免在接口没有有效 Apifox 网页地址时提供无效操作。      | 当前接口无法解析出 Apifox 网页地址时，不显示“去改 mock”按钮。                                         | 已验证 |

## 非目标

- 不在扩展内编辑 Apifox Mock 数据。
- 不修改接口测试请求、响应展示、Mock 配置结构或浏览器权限。
- 不自动关闭测试结果弹框。
