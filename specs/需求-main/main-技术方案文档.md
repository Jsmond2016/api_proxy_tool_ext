# main 技术方案文档

## 开发分支

`main`

## 方案概览

提取接口 Apifox 网页地址解析逻辑，由接口表格名称链接和测试按钮共同复用。接口表格将解析后的地址传给测试按钮；测试结果弹框仅在地址有效时，于“关闭”按钮左侧渲染“去改 mock”链接按钮，并使用新标签页安全打开目标页面。对于已不再需要的迭代信息能力，从 UI、缓存访问和存档流程中移除其运行时实现，并同步收敛用户文档；历史存档采用宽松读取，不因遗留的 `iterationInfo` 字段中断其他数据恢复。

## 技术决策

- 直接复用表格当前的链接优先级：接口记录 `link` 优先，项目 ID 与数字接口 ID 生成的地址作为兜底。
- 跳转属于用户主动触发的外部页面打开操作，不新增网络请求、数据写入、权限、迁移或不可逆影响。
- 不通过 Mock URL 反推 Apifox 页面，避免生成不可靠地址。
- 无有效 Apifox 地址时隐藏操作，不显示点击后报错的按钮。
- R4 采用完整下线而非仅隐藏按钮，避免留下无法进入但仍持续读写的迭代信息逻辑。
- 保留 Apifox tag 本身及按 tag 命名存档的行为；只移除 tag 关联的需求、技术、原型、测试用例和排期文档。
- 不主动删除 `chrome.storage.local` 中的旧迭代信息；运行时代码停止读取和写入该键。
- `ArchiveData` 不再声明或生成 `iterationInfo`，但 IndexedDB 中已有对象允许携带额外字段，恢复流程只读取仍受支持的属性，以兼容旧存档。
- R4 无 API、权限或数据库迁移；用户可见影响是相关入口、展示与复制能力消失。删除实现文件属于可恢复的源码变更，但功能下线本身需要用户确认。
- 实施模型：GPT-5 Codex。
